# 1. ОДНОЗНАЧНОЕ ОПРЕДЕЛЕНИЕ ЦЕЛЕЙ, КОНТЕКСТА И ДОПОЛНЕНИЙ

**Глобальная цель проекта:**
Инженерное проектирование и программная реализация монолитной, износоустойчивой рабочей станции DevOps на базе Windows 11 Enterprise LTSC IoT 24H2. Фундаментальные ИТ-императивы среды: полная ликвидация телеметрии и фонового I/O-шума (снижение WAF для SSD), демонтаж VBS/HVCI/LSA для минимизации DPC Latency и прямого доступа Thread Director к архитектуре CPU, обеспечение нативной коэкзекуции (co-execution) гипервизоров WSL2, Docker Engine и VMware Workstation Pro (строго через Windows Hypervisor Platform API).

**Глобальная цель репозитория (Контрольного контура ИИ):**
Трансформация GitHub-репозитория в детерминированную, самоактуализирующуюся базу знаний и сборочный конвейер (Digital Twin). Репозиторий должен аппаратно направлять автономного ИИ-агента, исключая семантические галлюцинации за счет внедрения жесткого ИТ-словаря, графа зависимостей сущностей, CRUD-протоколов иммутабельности и 4-стадийного пайплайна принудительных актуальных исследований.

**Однозначное определение Сущностей и Связей (Semantic Graph):**
1.  **[SC-XXX] Success Criteria (Критерии успеха):** Фундаментальные константы проекта (например, `SC-VBS-HVCI-DISABLED`). *CRUD:* Чтение (R). Создание/Обновление/Удаление запрещено (IR-0).
2.  **[PAT-XXX_date_name] Pattern (Паттерн):** Изолированный, верифицированный инженерный механизм (например, `PAT-011_2024-10-25_ntfs_deny_system.md`). Хранится в `/docs/patterns/`. *CRUD:* Чтение (R), Создание (C) при нахождении уникальных механизмов, Обновление (U) даты и содержимого при выявлении устаревания через Web-Search.
3.  **[ADR-XXX] Architecture Decision Record (Решение):** Документ, обосновывающий применение конкретного Паттерна для достижения Критерия Успеха в рамках конкретной сборки. Хранится в `/builds/devops_ltscIot24h2/docs/decisions/`. *Связи:* Обязан ссылаться на `[PAT]` и `[SC]`.
4.  **[STG-XXX] Stage (Стадия алгоритма):** Хронологический шаг конвейера. Хранится в `/builds/devops_ltscIot24h2/algorithm/`. *Связи:* Обязан ссылаться на `[ADR]`.
5.  **[STUB] Shadow Stub (Теневая заглушка):** Markdown-репрезентация бинарного файла на физическом USB-носителе.
- Внутренняя структура разделов `VENTOY` и `AUXILIARY` является объектом исследований AI-агента. Любое предложение по их рефакторингу инициирует `GATE_STRUCTURE`.
- Логика процессов развертывания ОС распределяется строго между `algorithm/manual/` и `algorithm/auto/`.
- Исполняемые файлы разрабатываются агентом в `scripts/` и транслируются CI/CD конвейером (или вручную оператором) в соответствующие папки на раздел **AUXILIARY**.
- Карты дисков, скрипты разметки USB, профили конфигурации DiskGenius и математика 4K-выравнивания NVMe документируются агентом строго в `docs/storage/`.
